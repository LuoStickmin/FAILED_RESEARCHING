# 02 · D750 AVI / 320×240 30i：能力位不是复用器

> 状态：❌ 完全不成立（补丁路径）
> 日期：2026-11-12
> 对象：Nikon D750，EXPEED 4，`D750_0115` / `b1010_115a.bin`
> 性质：只读静态分析；**没有修改、重打包或刷入任何固件**

## 目标

在 D750 菜单里加入 AVI 录像（Motion-JPEG）和 320×240 30i 低分辨率/隔行选项。

## 结论

**“在菜单里加一个 AVI 选项”和“相机能录 AVI”是两件事。按目前证据，后者不能
靠静态补丁做出来。**

D750 固件里确实有 `.AVI` 字符串，但它只出现在一个**平台通用的文件类型
注册表**里：每条记录是 `{格式 ID, 能力位, 扩展名, 长度, 读位函数, 写位函数}`。
`.AVI` 是 ID 5、能力位 `0x10`，读写的是某个对象 `+0x29` 字节的第 4 位——这是
“文件类型/能力标记”，不是 AVI 复用器，也不是 AVI 编码器。

## 证据

### 1. 文件类型注册表

模块偏移 `0x131C8BC`，`0x18` 字节步长：

| 偏移 | ID | 能力位 | 扩展名 | 读位函数 | 写位函数 |
| --- | --- | --- | --- | --- | --- |
| `0x131C8BC` | 1 | `0x01` | `.JPG` | `0x901C6BB7` | `0x901C6BBF` |
| `0x131C8D4` | 2 | `0x02` | `.NEF` | `0x901C6BCB` | `0x901C6BD5` |
| `0x131C8EC` | 3 | `0x04` | `.TIF` | `0x901C6BE1` | `0x901C6BEB` |
| `0x131C904` | 4 | `0x08` | `.NDF` | `0x901C6BF7` | `0x901C6C01` |
| `0x131C91C` | 5 | `0x10` | `.AVI` | `0x901C6C0D` | `0x901C6C17` |
| `0x131C934` | 6 | `0x20` | `.MOV` | `0x901C6C23` | `0x901C6C2D` |
| `0x131C94C` | 8 | `0x80` | `.~OV` | `0x901C6C4F` | `0x901C6C59` |

`.AVI` 字符串本身在模块 `0x12665A2`，`.MOV` 在 `0x12665A7`，`.~OV` 在
`0x12665AC`（从命名看是录制中的临时/未完成文件扩展名）。

读函数（Thumb `0x901C6C0C`）只是：

```asm
ldrb.w  r0, [r0, #0x29]   ; 取文件类型能力字节
```

写函数同理，只是置/清一个位。**这是能力标记，不是 AVI 复用器。**

### 2. 没有 AVI/RIFF 写入器

`avih`、`movi`、`idx1`、`LIST`、`strh`、`strf`、`hdrl`、`00dc`/`00db` 在三个
模块里全部 0 命中；仅有的 `RIFF` 是 WAV（PCM 音频）模板。

固件里有完整的 **MOV/QuickTime 写入器**：`moov/mdat/ftyp/mvhd/trak/udta`
原子常量在模块 `0xBD420`，视频编码是 H.264（`avcC`/`avc1`）。

### 3. 没有 Motion-JPEG 视频通路

`MJPG`/`MJPEG`/`jpeg`（小写 sample entry）全部 0 命中。固件里有 JPEG 任务
（`JPEGM`/`JPEGS`）和 JPEG 缩放表，但没有 MJPEG 码流/AVI 写入路径。

### 4. 没有 320×240 或隔行录像模式

电影模式表（模块 `0x2AA99C`，22 项）只支持 `1920×1080`、`1280×720`、
`640×424`，全部是逐行 timebase（60/50/30/25/24p）。

`320×240` 只出现在 JPEG/缩略图缩放阶梯里；`30i` 只作为通用帧率标签存在，
D750 用户可见的隔行选项只有 HDMI 输出的 `1080i`。

### 5. 菜单里没有 `Movie file type`

英文/中文 UTF-16 池中 `Movie file type`、`AVI` 均 0 命中。D750 的 Movie
settings 只有 `Frame size/frame rate` 与 `Movie quality`，前者只有 7 个
1080p/720p 选项。

## 为什么“完全不成立”

否定的是“静态补丁/复用现有数据”这条路径，因为至少缺四层：

1. **容器写入器**：没有 AVI/RIFF 写入器；
2. **视频编码路径**：没有 MJPEG，只有 H.264-in-MOV；
3. **采集模式**：没有 320×240、没有隔行；
4. **菜单/设置**：没有 `Movie file type`，没有 `AVI` 标签，没有枚举与持久化。

只加菜单项，最多得到一个按下去没有写入路径的空项；要真正录 AVI，需要新增
写入器、采集路径、菜单与设置、文件系统与回放——属于功能开发/移植。

## 如果仍要做

真实成本大致是：

1. 实现 AVI/RIFF 容器写入器（或移植 MJPEG-in-AVI 路径）；
2. 增加 MJPEG 编码或把 H.264 封装进 AVI（后者需要核实回放兼容性）；
3. 增加 320×240 或隔行采集/缩放路径；
4. 增加菜单项、设置枚举与持久化（36 种语言池都要处理）；
5. 文件系统、回放、缩略图兼容；
6. 真机验证与回退方案。

这不是“改几个字节”的补丁。

## 边界

- 只做只读静态分析，没有修改固件；
- 没有生成可刷镜像；
- 固件版权属于 Nikon；本文只记录偏移、字符串和结论；
- 结论针对 `D750_0115` / `b1010_115a.bin`；其他机型/版本未逐一验证。
